# y4p

**Wayland統合型クリップボード・インフラストラクチャ**

`y4p` は、Wayland向けにネイティブ設計された、スタンドアロンのクリップボードマネージャーです。

デーモンはひとつだけ。監視用と提供用でプロセスを分ける必要はありません。単一のバイナリが、クリップボードの監視、履歴の復元、そして永続化までを担います。

</div>

## 動作環境

`y4p` が対象とするのは **wlroots系のコンポジタ** です。Sway、Hyprland、その他wlroots上に構築された環境が該当します。

X11向けの互換レイヤーではなく、`ext-data-control-v1` プロトコルに直接依存しています。これは意図的な設計上の選択であり、手抜きではありません。

裏を返せば、このプロトコルを実装していないコンポジタでは動作しません。本稿執筆時点では、KWinがその代表例です。お使いの環境で対応しているか不安な場合は、インストール前にコンポジタのWaylandプロトコル一覧をご確認ください。

## y4pを選ぶ理由

**Unified Standalone Architecture.**
バイナリはひとつ、デーモンもひとつ。監視・提供・永続化がすべて同一プロセス内で完結するため、同期を保つべき対象も、ゾンビとして残る心配もありません。

**High-Capacity Hybrid Storage.**
テキストとメタデータは、高速検索可能なSQLiteデータベースへ。スクリーンショットやGIFなどの大きなバイナリは、重複排除されたファイルシステムキャッシュへ。両者は互いの領分を侵しません。70MBを超えるアイテムでも同様です。

**Script-First Stable IDs & Strict CLI.**
すべてのレコードには、表示位置とは独立した不変のIDが割り当てられます。未定義のフラグを即座に拒絶するパーサと組み合わせることで、`fzf` や `rofi`、シェルパイプラインの中でも予測可能に振る舞います。対話的な利用だけを想定した設計ではありません。

**Zero-Loss Integrity & Pin Protection.**
Pinを立てたレコードには、履歴のローテーションが決して触れません。その後どれだけコピーを重ねても、恒久的に除外され続けます。スキーマのマイグレーションも段階的に設計されているため、アップデートを挟んでも既存の履歴が書き換わったり失われたりすることはありません。

## コマンド一覧

どんなことができるツールか、ざっと把握するための一覧です。詳細なフラグや使用例は `y4p help` を参照してください。

| コマンド | 概要 |
| :--- | :--- |
| `daemon` | バックグラウンド監視とIPCリスナーを開始します。 |
| `list` / `search` | クリップボード履歴を閲覧・検索します。 |
| `copy-to` | 履歴のエントリを現在のクリップボードへ復元します。 |
| `show` | レコードの中身を直接確認します。 |
| `store` / `paste-from` | 標準入力から手動で取り込む、またはOSクリップボードを直接読み出します。 |
| `pin` / `unpin` | レコードを自動ローテーションから保護・解除します。 |
| `delete` / `wipe` | 1件を削除する、または履歴を全消去します。 |
| `status` / `pause` / `resume` | デーモンの監視状態を確認・制御します。 |

## クイックスタート

まずビルドします。

```bash
cargo build --release
sudo cp target/release/y4p /usr/local/bin/
```

デーモンを起動します。

```bash
y4p daemon
```

Zsh補完を有効にする場合（任意）。`compinit` の実行前に、補完ディレクトリを `fpath` に追加してください。

```zsh
fpath+=(/path/to/y4p/completions)
```

これだけです。

各コマンドの詳細なフラグや使用例は、以下で確認できます。

```bash
y4p help
```
